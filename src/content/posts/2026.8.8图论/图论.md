---

#### 1. 对应图建立“邻接矩阵” `map`

根据图片中箭头的指向（有向图）：
* **1 号** 只有一个箭头指向 **2**
* **2 号** 只有一个箭头指向 **3**
* **3 号** 有两个箭头，指向 **1** 和 **4**
* **4 号** 只有一个箭头指向 **2**

写成矩阵形态（有路记为 `通`，没路记为 `x`）：

| 起点  终点 | 1号 | 2号 | 3号 | 4号 |
| --- | --- | --- | --- | --- |
| **1号** | x | **通** | x | x |
| **2号** | x | x | **通** | x |
| **3号** | **通** | x | x | **通** |
| **4号** | x | **通** | x | x |

初始记事本：`vis = [0, 0, 0, 0, 0]`

---

#### 2. 逐步模拟推演

##### 【第 1 步】启动 `dfs(1)`

1. `vis[1]` 为 0，标记 `vis[1] = 1`。
2. 控制台**打印：`1`**。
3. 跑 `for` 循环寻找 1 的下家（检查 `map[1][i]`）：
    - `i=1`: 无路
    - `i=2`: **有路！** 暂停当前循环，发起调用 **`dfs(2)`**。

---

##### 【第 2 步】深入 `dfs(2)`

1. `vis[2]` 为 0，标记 `vis[2] = 1`。
2. 控制台**打印：`2`**。
3. 跑 `for` 循环寻找 2 的下家（检查 `map[2][i]`）：
    - `i=1, 2`: 无路
    - `i=3`: **有路！** 暂停当前循环，发起调用 **`dfs(3)`**。

---

##### 【第 3 步】深入 `dfs(3)`

1. `vis[3]` 为 0，标记 `vis[3] = 1`。
2. 控制台**打印：`3`**。
3. 跑 `for` 循环寻找 3 的下家（检查 `map[3][i]`）：
    - `i=1`: **有路！**（箭头 3 $\rightarrow$ 1）。暂停当前循环，发起调用 **`dfs(1)`**。

---

##### 【第 4 步】再次进入 `dfs(1)`（死循环拦截！）

1. 检查 `if (vis[1])`，发现 `vis[1]` 已经是 1 了！
2. **触发撤退**：执行 `return;`，销毁当前函数。
3. **退回到哪里？** 回到上一层的 **`dfs(3)`** 的 `for` 循环中。

---

##### 【第 5 步】回到 `dfs(3)`（继续找别的路）

1. 刚刚 `dfs(3)` 停在 `i=1`。现在继续循环，`i++` 变成 `i=2`：
    - `i=2`: 无路
    - `i=3`: 无路
    - `i=4`: **有路！**（箭头 3 $\rightarrow$ 4）。暂停当前循环，发起调用 **`dfs(4)`**。

---

##### 【第 6 步】深入 `dfs(4)`

1. `vis[4]` 为 0，标记 `vis[4] = 1`。
2. 控制台**打印：`4`**。
3. 跑 `for` 循环寻找 4 的下家（检查 `map[4][i]`）：
    - `i=1`: 无路
    - `i=2`: **有路！**（箭头 4 $\rightarrow$ 2）。暂停当前循环，发起调用 **`dfs(2)`**。

---

##### 【第 7 步】再次进入 `dfs(2)`（拦截！）

1. 检查 `if (vis[2])`，发现 `vis[2]` 已经是 1 了！
2. **触发撤退**：执行 `return;`，销毁当前函数。
3. **退回到哪里？** 回到上一层的 **`dfs(4)`** 的 `for` 循环中。

---

##### 【第 8 步】收尾阶段（逐层安全退栈）

1. **在 `dfs(4)` 中**：`i=2` 试完了，继续看 `i=3, 4`，都没路。`dfs(4)` 运行完毕，**撤退回 `dfs(3)`**。
2. **在 `dfs(3)` 中**：`i=4` 试完了，循环结束，**撤退回 `dfs(2)`**。
3. **在 `dfs(2)` 中**：`i=3` 试完了，`i=4` 没路，循环结束，**撤退回 `dfs(1)`**。
4. **在 `dfs(1)` 中**：`i=2` 试完了，`i=3, 4` 没路，循环结束。

全程序运行完毕！

邻接表 `vector<int> G[105]` 的核心思想是：**“只记有路的邻居，不浪费时间看没路的”**。

我们继续用刚才那张 4 个节点的图来一步步模拟 **`dfs(1)`** 的全过程。

---

#### 1. 对应图建立“邻接表” `G`

根据图片中箭头的指向，每个节点只记录它**直接能到达的下家列表**：

- **`G[1]`** = `{2}` （1 号只能去 2）
- **`G[2]`** = `{3}` （2 号只能去 3）
- **`G[3]`** = `{1, 4}` （3 号能去 1 和 4）
- **`G[4]`** = `{2}` （4 号只能去 2）

初始记事本：`vis = [0, 0, 0, 0, 0]`

---

#### 2. 代码的核心区别：范围 `for` 循环

注意这段新代码里的 `for` 循环：

```cpp
for (int to : G[node]) {
    dfs(to);
}
```

它的意思是：**不需要用 `1` 到 `n` 去挨个试了，直接取出 `G[node]` 动态数组里的每一个邻居 `to`，直接深度搜索！**

    - 取出 `to = 2`，发起调用 **`dfs(2)`**。

---

##### 【第 2 步】深入 `dfs(2)`

1. `vis[2]` 为 0，标记 `vis[2] = 1`。

3. 遍历 `G[2]`（里面只有数字 `3`）：

1. `vis[3]` 为 0，标记 `vis[3] = 1`。
2. 控制台**打印：`3`**。
3. 遍历 `G[3]`（里面有数字 `{1, 4}`）：
    - 先取出第一个邻居 `to = 1`，发起调用 **`dfs(1)`**。

1. 刚才在 `G[3]` 里处理完了 `1`，现在自动取出下一个邻居：**`to = 4`**。

2. **在 `dfs(3)` 中**：`G[3]` 里的元素（`1` 和 `4`）已遍历完毕。`dfs(3)` 运行结束，**撤退回 `dfs(2)`**。
3. **在 `dfs(2)` 中**：`G[2]` 里的元素（只有 `3`）已遍历完毕。`dfs(2)` 运行结束，**撤退回 `dfs(1)`**。
4. **在 `dfs(1)` 中**：`G[1]` 里的元素（只有 `2`）已遍历完毕。

---

#### 4. 总结：邻接表 vs 邻接矩阵

| 对比项 | 邻接矩阵 (`map[105][105]`) | 邻接表 (`vector<int> G[105]`) |
| --- | --- | --- |
| **找邻居的方式** | 必须跑 `for(i=1; i<=n; i++)` 遍历所有节点，即使没路也要检查 | 只遍历 `G[node]` 里真正存在的邻居 |
| **执行轮数** | 会有很多轮空跑（检查到无路/负无穷） | **零废动作**，拿到就是有路的邻居 |
| **最终打印** | `1 -> 2 -> 3 -> 4` | `1 -> 2 -> 3 -> 4` （完全一致） |

邻接表这种写法的 `for (int to : G[node])`（范围 for 循环）在现代 C++ 算法题里是最推荐、也最常考的形式！

代码解释

---


这句话是 C++11 引入的 **范围 for 循环（Range-based for loop）**，俗称“基于范围的遍历”。

用大白话解释，它的意思就是：
**“把 `G[node]` 里的每一个邻居节点依次取出来，临时起个名字叫 `to`，然后执行大括号里的代码。”**

---

##### 拆解这个语法的结构

```cpp
for (int to : G[node])
```

- **`G[node]`**：是一个容器（在代码里是 `vector<int>` 动态数组），里面存着当前节点 `node` 能到达的所有邻居顶点。
    - 例如：如果 `G[3]` 里面存着 `{1, 4}`，那这个容器里就有两个数：1 和 4。
- **`:`（冒号）**：代表“从……里面依次取出”。
- **`int to`**：定义一个临时变量 `to`（也就是 destination / “去往哪里” 的简称）。
    - 第一轮循环：`to` 的值自动变成第一个元素 `1`。
    - 第二轮循环：`to` 的值自动变成第二个元素 `4`。

---

##### 它等价于传统写法

如果你觉得冒号写法看着生疏，它完全等同于下面这种我们最熟悉的写法：

```cpp
// 传统下标遍历写法
for (int i = 0; i < G[node].size(); i++) {
    int to = G[node][i]; // 取出第 i 个邻居
    dfs(to);
}
```

两者效果一模一样，但 `for (int to : G[node])` 不需要你自己去算数组长度 `size()`，也不用手动写 `i++` 和下标访问，不容易写错界，在现代 C++ 里非常常用。

### 重点对比：你图片里的**错误代码**会发生什么？

错误代码两处致命问题：

1. 没有 `vis[node]=1` 标记起点
2. 循环写死 `G[node]`，node 永远 = 1，只读取`G[1]={2}`

#### 错误代码运行过程：

1. que.push (1)，队列 [1]，vis [1] 还是 0
2. 取出 t=1，打印 1，弹出队列变空
3. 只循环 G [1] 的 to=2：vis [2]=0 → vis [2]=1，push (2)，队列 [2]
4. 下一轮 t=2，**依旧循环 G [1]={2}**，to=2 已经标记，无事发生
5. 队列永远卡在 2，再也访问不到 3、4，直接遍历不全；
6. 如果图环路更复杂，缺少 vis 标记还会无限往队列塞节点，程序卡死死循环。

### 大白话总结

1. `G[t]` 跟着当前处理的节点 t 变化，才能拿到每个点自己的邻居；
2. 入队立刻打 vis 标记，有环也不会重复走、不会死循环。
